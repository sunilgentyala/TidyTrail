TidyTrail

Finds duplicate and large files in an iOS folder you pick — and writes a text log of exactly what it deleted, before it deletes anything.

View source on GitHub How it works on iOS

What it does

A focused storage-cleanup tool built around one idea: never delete silently. Every run leaves a paper trail.

Pick a folder

Grant access to one folder at a time through the standard iOS Files picker — an "On My iPhone" folder, or an iCloud Drive folder.

Find what's worth clearing

Exact duplicates are found by content hash, not just name or size. The largest files in the folder are surfaced too.

Delete with a log

Before anything is removed, TidyTrail writes a manifest to Files > TidyTrail Logs, then updates it with the real outcome — deleted, or failed and why.

Honest about iOS sandboxing

iOS does not let third-party apps scan "the whole phone" or clear another app's cache — there's no such API, and Apple rejects apps that claim otherwise. TidyTrail is scoped to what's actually possible.

What TidyTrail can do

  • Scan a folder you explicitly grant access to via the Files picker
  • Find exact duplicate files by content, and the largest files
  • Delete files you select, with a before-and-after text log
  • Show device-wide total/available storage (public API)

What no iOS app can do

  • Scan or delete other apps' caches or documents
  • Clear OS-level temp files
  • See a device-wide breakdown of storage by app

Architecture

SwiftUI app on top of a pure-Swift core package, with the Xcode project generated rather than hand-maintained.

TidyTrailCore

Foundation + CryptoKit only, no UIKit. Scanning, duplicate detection, and the delete-then-log engine, covered by XCTest unit tests.

XcodeGen

project.yml is the source of truth — the .xcodeproj is generated, so the project stays diffable and editable without Xcode.

GitHub Actions CI

Runs swift test and a full simulator build on a macOS runner on every push — the actual build/test loop, since development happens from a machine with no local Xcode.
